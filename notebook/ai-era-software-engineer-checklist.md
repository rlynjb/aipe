# AI-Era Software Engineer Checklist

> **Core reminder:** AI can generate code. My value is understanding the system, directing the AI, validating its work, and explaining my decisions.

## 1. Strengthen computer-science fundamentals

* [ ] Study data structures through real application features.
* [ ] Understand time and space complexity.
* [ ] Practice arrays, maps, sets, stacks, queues, trees, and graphs.
* [ ] Learn BFS, DFS, cycle detection, topological sorting, and shortest paths.
* [ ] Review databases, networking, concurrency, caching, and operating-system fundamentals.
* [ ] Connect every concept to code inside one of my applications.
* [ ] Explain when and why I would choose one structure or algorithm over another.

## 2. Develop systems thinking

Before asking AI to implement a feature:

* [ ] Define the actual user problem.
* [ ] Identify the system boundaries.
* [ ] Map the full data and request flow.
* [ ] Identify components, services, databases, APIs, and external dependencies.
* [ ] Define the important invariants and business rules.
* [ ] Consider failure modes and unusual inputs.
* [ ] Consider security, performance, scalability, and maintainability.
* [ ] Decide what belongs in the client, server, database, or background worker.
* [ ] Sketch at least one alternative design before committing.

```text
User problem
    ↓
Domain model
    ↓
System design
    ↓
Data structures and algorithms
    ↓
AI-assisted implementation
    ↓
Testing and verification
```

## 3. Use AI as an engineering tool—not an authority

* [ ] Give AI constraints and context instead of vague feature requests.
* [ ] Ask AI to explain its proposed architecture before generating code.
* [ ] Request multiple approaches with trade-offs.
* [ ] Break large tasks into small, reviewable changes.
* [ ] Inspect the generated code before accepting it.
* [ ] Verify unfamiliar APIs against official documentation.
* [ ] Avoid merging code I cannot explain.
* [ ] Keep important architectural decisions under my control.
* [ ] Use AI to accelerate implementation, debugging, testing, and research.
* [ ] Notice when AI adds unnecessary complexity or abstractions.

## 4. Practice catching AI mistakes

For every generated feature, check:

* [ ] Is the implementation logically correct?
* [ ] Are there missing edge cases?
* [ ] Are the types accurate?
* [ ] Are errors handled meaningfully?
* [ ] Are asynchronous operations safe?
* [ ] Could race conditions occur?
* [ ] Is user input validated?
* [ ] Are authentication and authorization separate and correct?
* [ ] Are secrets or private data exposed?
* [ ] Are database operations transactional where necessary?
* [ ] Are queries unnecessarily expensive?
* [ ] Does the code introduce tight coupling?
* [ ] Is the abstraction useful or merely decorative?
* [ ] Do the tests verify behavior rather than implementation details?
* [ ] Would this still work with substantially more users or data?

## 5. Be able to explain every decision

After completing a feature, answer without relying on AI:

* [ ] What problem does this feature solve?
* [ ] How does data move through the system?
* [ ] Why did I choose this architecture?
* [ ] Why did I choose this data structure?
* [ ] What alternatives did I reject?
* [ ] What trade-offs did I accept?
* [ ] What assumptions does the implementation make?
* [ ] Where is it most likely to fail?
* [ ] What is its time and space complexity?
* [ ] How would I test it?
* [ ] How would I redesign it for 10× or 100× usage?
* [ ] Which parts were generated by AI, and how did I verify them?

## 6. Improve problem-solving ability

* [ ] Restate the problem before writing code.
* [ ] Separate requirements from possible implementations.
* [ ] Create a small example manually.
* [ ] Identify inputs, outputs, constraints, and invariants.
* [ ] Decompose the problem into independently testable parts.
* [ ] Choose the simplest correct solution first.
* [ ] Measure before optimizing.
* [ ] Compare the result against a known-good example.
* [ ] Practice debugging from evidence rather than guessing.
* [ ] Write down why a bug occurred, not only how it was fixed.

## 7. Learn to operate agentic systems

The video specifically emphasizes being able to work quickly with new agentic systems.

* [ ] Learn how agents use tools, memory, context, and structured outputs.
* [ ] Understand the difference between a workflow and an autonomous agent.
* [ ] Practice defining agent responsibilities and boundaries.
* [ ] Design human approval points for consequential actions.
* [ ] Add retries, timeouts, fallbacks, and failure handling.
* [ ] Trace agent decisions and tool calls.
* [ ] Build evaluations for correctness and reliability.
* [ ] Test prompt and model changes against the same evaluation set.
* [ ] Track latency, cost, failure rates, and output quality.
* [ ] Avoid adding agents when deterministic code would be more reliable.

## 8. Continue developing the Claude study-material plugin

For every AI-built application, have it generate:

* [ ] A system overview.
* [ ] A request-flow walkthrough.
* [ ] A component and dependency map.
* [ ] CS fundamentals used by each feature.
* [ ] Data-structure and algorithm explanations.
* [ ] Architecture-decision questions.
* [ ] Alternative implementation approaches.
* [ ] Complexity analysis.
* [ ] Edge cases and failure scenarios.
* [ ] Security and performance review questions.
* [ ] AI-generated-code audit exercises.
* [ ] Interview questions grounded in the actual codebase.
* [ ] A redesign challenge.
* [ ] A “teach this without looking at the code” exercise.

The plugin should not only produce explanations. It should test whether I can **retrieve and apply** the knowledge:

* [ ] Require me to answer before revealing the explanation.
* [ ] Ask follow-up questions when my answer is incomplete.
* [ ] Generate small coding or debugging exercises.
* [ ] Revisit concepts I previously struggled with.
* [ ] Make me defend a design rather than merely recognize it.
* [ ] Track concepts demonstrated across multiple projects.

## 9. Build proof of engineering ability

For every portfolio project:

* [ ] Write a clear problem statement.
* [ ] Include a system-design diagram.
* [ ] Document important architectural decisions.
* [ ] Describe where AI was used.
* [ ] Explain how generated work was verified.
* [ ] Include tests and meaningful evaluation results.
* [ ] Document one difficult bug and the investigation process.
* [ ] Show an initial design and what changed after learning.
* [ ] Explain performance, reliability, and security considerations.
* [ ] Prepare a five-minute verbal walkthrough.
* [ ] Prepare a deeper technical walkthrough.
* [ ] Keep the repository and commit history understandable.

## 10. Weekly practice loop

* [ ] Learn one fundamental relevant to my current feature.
* [ ] Implement or inspect it in a real application.
* [ ] Let AI propose an implementation.
* [ ] Review the proposal for correctness and complexity.
* [ ] Write tests for normal, edge, and failure cases.
* [ ] Explain the completed feature in my own words.
* [ ] Document one architectural decision and its trade-offs.
* [ ] Add the lesson to my Claude study plugin.
* [ ] Rebuild one small part without copying the generated answer.
* [ ] Record what I can now explain that I could not explain last week.

## My priority order

```text
1. Systems thinking
2. Problem decomposition
3. CS and DSA fundamentals
4. Explaining technical decisions
5. Detecting AI mistakes
6. Testing and evaluation
7. Operating agentic systems
8. Communicating and demonstrating the work
```

The standard to aim for is:

> **I do not need to manually type every line. I need to understand the problem, direct the implementation, detect when it is wrong, and defend the final design.**
