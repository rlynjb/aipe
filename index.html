A personal notebook for learning AI engineering

A workspace I built
for my own learning.

aipe is where I keep the long-form notes, prompt templates, and spec scaffolds I reuse across projects. It also generates a book-style study guide of any codebase I'm working in, formatted the way I personally like to learn.

What's in here

Three things live in this repo.

Everything is plain markdown — readable on GitHub, editable in any editor, version-controlled with the rest of my work.

01 · Books

Long-form notes I'm writing

Topic-by-topic references I work through as I learn. Currently covering AI engineering, ML and front-end interview prep, prompt engineering, and relational data systems. Diagrams, prose, and worked examples in one place.

02 · Prompts

Prompt templates I reuse

The prompts I keep coming back to — curriculum framings, review protocols, story checklists. Each one is a markdown file I can paste into any agent or adapt for a new project.

03 · Specs

Spec scaffolds for my agent

Markdown templates my coding agent fills in before writing code. One per kind of work — feature, debugging, refactor, study, and others. Packaged as slash commands for Claude Code and Codex CLI.

/aipe:study

A book-style study guide of any codebase I'm working on.

The study spec is the one I built most carefully for myself. Point it at a codebase and it generates a directory of files — one per concept — that walk me from a curiosity hook to verified understanding. The shape, ordering, and conventions are tuned to how I personally learn.

  • One concept per file Each file walks a single pattern end-to-end. Open one, work through it in a sitting, then move on. No skimming, no half-understood concepts carrying forward.
  • Prose first, diagram as the recap The "how it works" prose explains the mechanics; the primary diagram lands afterwards as a visual summary of what I just read. The order is deliberate.
  • Four sections, mapped to my curriculum System design, DSA, AI engineering, and machine learning. Each section has its own subdirectory, README index, and one file per pattern actually found in the codebase.
  • Execution traces in the DSA files Line-by-line walkthroughs of what a computer does at every step. The part most explanations skip, written out.
  • "Validate" blocks send me back to real code After each concept, the validate scenarios point to specific file:line ranges in the codebase. The guide explains; the code is the ground truth.
  • Tech reference with honest labels Every concept includes a "leading today" tag — adoption-leading for battle-tested patterns, innovation-leading for fast-moving areas — with a runner-up named where the codebase already uses the leader.
  • Frontend primitives instead of analogies Concepts are anchored to real software I've worked with (React props, function calls, HTTP), not to physical-world metaphors that dissolve under scrutiny.
  • Auto-detects existing guides, updates only what drifted Re-running on a codebase that already has a guide diffs against the code and the template, then patches only the pieces that changed. No regenerating from scratch.

Install

If you want to use it too.

aipe is a plugin for Claude Code and Codex CLI. The agent in your session does the work using its own model — there's no separate binary, no API keys, no service to deploy.

Claude Code

In any Claude Code session:

/plugin marketplace add rlynjb/aipe /plugin install aipe@rlynjb-aipe

Codex CLI

From your terminal:

codex plugin marketplace add rlynjb/aipe
