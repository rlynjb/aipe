Concepts · System design · Your code as evidence

Core concepts to articulate fluently

  • Provider abstraction: why it matters, how getLLM() dispatches across 4 providers (Anthropic, OpenAI, Google, Ollama), what LiteLLM is in Python
  • Chain pattern: input → messages → LLM → parse → output, the 5 chains in buffr, why stripCodeBlock() is always needed
  • Query param dispatch: why buffr uses ?summarize / ?intent / ?suggest / ?paraphrase on a single endpoint, trade-offs vs separate endpoints
  • Tool token resolution vs LLM-directed tool use: {{tool:name}} pre-fetch in resolve-tools.ts vs suggestedActions in prompt-chain.ts — when to use each
  • Adapter compilation pattern: single source of truth (dev-items) compiled into 6 tool-specific output formats, pushed atomically via GitHub Trees API
  • 8 Blob stores: one-blob-per-record vs one-blob-per-project-as-collection, when each pattern breaks down
  • RAG vs fine-tuning: when to use each, cost/accuracy trade-offs
  • Streaming: SSE, chunked encoding, why it matters for LLM latency UX, time-to-first-token
  • Embeddings + vector search: cosine similarity, chunking strategy, pgvector vs Pinecone
  • Evals: LLM-as-judge, regression tests, semantic similarity scoring
  • On-device ML vs cloud: latency, privacy, cost trade-offs — when each is right
  • poselab's 5 detectors: staggered frame cadence, WASM singleton, why frame skipping prevents GPU saturation
  • Signal processing on ML output: EMA smoothing, joint angles, phase classification state machine
  • TOCTOU: what it is, the specific bug in buffr's one-blob-per-project stores, the sequential fix

Provider abstraction"I built getLLM() in lib/ai/provider.ts which dispatches to 4 providers — Anthropic Claude, OpenAI GPT-4o, Google Gemini, and local Ollama — without any chain code changing"
Chain architecture"buffr has 5 chains in lib/ai/chains/ — summarizer, intent detector, next-step suggester, paraphraser, and prompt-chain. All follow the same pattern: system message + human message + stripCodeBlock() + JSON.parse()"
Query param dispatch"session-ai.ts dispatches to 4 chains via ?summarize / ?intent / ?suggest / ?paraphrase. One file, one provider setup, four AI operations — practical for serverless."
Tool token resolution"buffr resolves {{tool:github_list_issues}} tokens in resolve-tools.ts before the LLM call. The model sees live API data, not template syntax."
Adapter compilation"The .dev tab compiles AI rules and skills into 6 adapter files (CLAUDE.md, .cursorrules, copilot-instructions, etc.) and commits them atomically via GitHub's Trees API in a single commit."
8 Blob stores"buffr uses 8 Netlify Blobs namespaces. Prompts use one-blob-per-record (each prompt is its own key). Manual actions use one-blob-per-project-as-array — that's where the TOCTOU bug appeared."
On-device ML"poselab runs 5 MediaPipe detectors simultaneously with staggered frame cadences — pose every frame, face/hand/gesture every 2nd, segmentation every 3rd. contrl uses pose-only at 30fps."
Signal processing"I built rep counting as a signal processing pipeline — EMA smoothing, joint angle via dot product, phase state machine (idle→down→bottom→up) — on top of MediaPipe landmark output."
